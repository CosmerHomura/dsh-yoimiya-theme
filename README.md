# 宵宫主题 · dsh-yoimiya-theme

为 DeepSeek Harness Web GUI 制作的《原神》宵宫主题。

两个时刻：**夏祭夜**是烟花下的暖靛黑，**和纸昼**是和纸米色的暖光。配色跟随
DSH 的明暗偏好自动切换，不需要额外设置。

主题里有两样**活的东西**——一层自己画的烟花粒子，和一个能装你自己歌单的
本地播放器。两样都不联网。

---

## 创意

### 两个时刻，而不是两套配色

多数主题的"亮 / 暗"是把同一套颜色反相。这里不是：两档各有自己的意象。

|  | 暗档「夏祭夜」 | 亮档「和纸昼」 |
| --- | --- | --- |
| 意象 | 夏夜、烟花、灯笼、温热的夜风 | 和纸、暖光、青海波、墨 |
| 窗口底色 | `#14111C` 暖靛黑 | `#FAF3E8` 和纸米 |
| 正文 | `#EDE3D3` 暖米白 | `#33261C` 墨棕 |
| 品牌橙 | `#E08A3C` | `#B5502A` |
| **正文对比度** | **13.99:1** | **13.28:1** |

同一个"品牌橙"在两档里是两个值：暗档要提亮才在靛黑上读得清，亮档要压深才在
纸色上读得清。硬套一个值，必然有一档是糊的。

### 背景会看你在做什么

壁纸在首页全亮；**一旦开始对话，它自动退成氛围层**，把屏幕中心让给正文。

这是整套设计里唯一一处"随状态变化"的地方，也是它和普通换色主题最大的区别：
主题先是一个阅读环境，然后才是一张画。所以护眼不是靠蒙一层压暗遮罩——那种
做法会把画面压闷——而是靠"该让位的时候让位"。

### 画面是算出来的，不是贴出来的

烟花、光柱、灯笼、金鱼、青海波弧、纸纹——除了那张壁纸，**没有一个像素来自
贴图**，全部由 CSS 渐变与手写 SVG 生成。除壁纸外的画面资源合计约 20 KB，
改配色也只是改数值。

侧边栏那个位置原本是官方标识，这里换成了自绘的金鱼（折叠态也有）。

## 烟花粒子

右下角烟花按钮 → 升起速度 / 密度 / 爆炸各三档，外加开关。

- 纯 Canvas 2D 实时模拟：引线带着尾迹上升，升到炸点炸开，火星受重力下坠、
  受空气阻力减速，再用 `destination-out` 逐帧淡出留下拖尾
- 四色调色板与主题 token 同源，不会出现"外部插件感"的荧光色
- **尊重系统的「减少动态效果」**：系统要求减少动效、而你没表过态时，默认关闭
- **切到别的窗口就停**，不在后台空转烧电
- 面板底部有一行「开销」读数：实测帧率、火星数、画布像素数。想知道这一层到底
  贵不贵，看这个数——帧率是按真实帧间隔算的，卡顿不会被抹平

## 本地音乐播放器

右下角音乐按钮 → 一个完整的播放器：封面区、播放 / 暂停、上一首 / 下一首、
进度条（点击跳转）、音量（**记住上次的值**）、可折叠的曲目列表。

### 曲库就是一个文件夹

没有清单文件要维护。**一首歌 = 一个音频文件**，文件夹本身就是曲库：

```
<DSH_HOME>/yoimiya-music/
├── 某首歌.mp3
├── 某首歌.jpg        ← 同名图片就是它的封面（可选）
└── 另一首.flac
```

Windows 桌面端 `<DSH_HOME>` 默认是 `%APPDATA%\dsh-desktop\harness`。
**打开音乐面板就能看到实际路径**，面板会直接告诉你（曲库为空时也会显示）。

### 两种添加方式，效果完全一样

1. **直接拖进去** —— 把音频文件（和同名封面图）丢进上面那个文件夹，然后收起
   再打开音乐面板（面板每次打开都会重读目录）
2. **用面板上的「添加歌曲」** —— 选音频（必须）与封面（可选）；封面可以在
   面板里拖动、用滚轮或滑块缩放，裁成 512×512 方图

**封面不是必须的**：没有封面的歌会显示主题的金鱼标识。

| | |
| --- | --- |
| 音频 | `.mp3` `.m4a` `.aac` `.ogg` `.oga` `.opus` `.wav` `.flac` `.webm` |
| 封面 | `.jpg` `.jpeg` `.png` `.webp` `.gif` `.avif` |

**本主题不内置任何音乐。** 曲库初始是空的，里面放什么完全由你决定——这是刻意
的：这个仓库不分发任何可能有版权问题的音频，只提供一个读你自己文件的播放器。

## 你的文件去哪了

**不上传。任何地方都不上传。**

「添加歌曲」做的事只有一件：**把你选的文件复制进你本机的一个目录**（就是上面
那个 `yoimiya-music`）。它经由应用自己的本地接口完成，而这个接口**只监听
`127.0.0.1`**——只有你这台机器连得上，同一局域网里的其他设备也连不上。

具体来说：

- 主题**不联网**，代码里没有任何对外请求；它引用的图片全部来自插件自己的本地路由
- 你放的歌和封面**留在本机**，不会被读取、分析或发送到任何服务器
- 卸载主题**不会删除**你的曲库文件夹——你的文件还是你的

## 观感与护眼

- **不用纯黑，也不用纯白。** 底色是暖靛黑与和纸米，正文是暖米白与墨棕——
  纯黑底上的白字会让人眼在明暗间反复大幅调节，这是长文阅读最累的一种组合
- 104 个色彩变量**逐项核算对比度**，正文 13.99:1 / 13.28:1（WCAG AA 的门槛
  是 4.5:1）；次要文本、占位符、语法高亮、错误 / 成功 / 警告色也各自达标
- **暖色系语法高亮**，替换默认的高饱和蓝与紫
- 会话激活项是一道橙色「引线」竖条
- 输入框占位文案换成宵宫台词（中英双语）
- 代码块用暖调底，但保持代码字体保真

## 性能

粒子是唯一一直跑着的东西，所以它被单独算过账——**先量后改，不靠感觉。**

这里有个很容易踩的误判：代码里写着 `MAX_SPARKS = 900`，看上去像"每帧要画 900 个
粒子"。按真实的生成参数算一遍，稳态其实只有 **约 55 个**（密度与爆炸拉满也只约
260 个），那个上限根本碰不到。所以瓶颈不在粒子绘制，而在**每帧用
`destination-out` 铺满整块画布做拖尾**——4K 屏按 1.5 倍是 7460 万字节的读改写，
**与粒子数无关**，哪怕把粒子调成"疏 + 慢"也照付。

据此做的处理：

- **画布后备存储按总像素数封顶**（约 220 万像素）。1080p 及以下输出完全不变，
  4K 屏自动退让——这一步同时也是给别人的机器兜底，不只是让开发机好看
- 窗口缩放合并到下一帧，且像素尺寸没变就不重建后备存储
- **切到后台自动停**（`visibilitychange`），不在后台空转烧电
- 主题卸载时把监听器一并摘干净——漏掉一个的后果不是"少停一次"，而是留下一条
  画向已移除画布的循环，谁也停不掉
- 换歌不再重建整个曲目列表，只改当前项的标记
- 封面裁切不再每次拖动都重建预览位图（预览与输出共用同一份变换）
- 曲库列举把封面匹配做成查表、文件大小并发取

面板底部有一行「开销」读数：实测帧率、火星数、画布像素数。**想知道这一层贵不贵，
看这个数** —— 帧率是按真实帧间隔算的，卡顿不会被抹平。

## 安装

### 应用内插件市场

设置 → 插件 → 搜索 `yoimiya` → 安装。

条目通过 [`awesome-dsh-plugin`](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)
目录分发；还没上架时，用下面两种方式中的任意一种。

### 命令行

```bash
dsh plugin --profile web add github:CosmerHomura/dsh-yoimiya-theme
```

### DSH Desktop 手动安装

桌面端不带 `dsh` 命令，用仓库内的脚本：

1. **完全退出 DSH Desktop**
2. 右键 `tools\install-local.ps1` →「使用 PowerShell 运行」
3. 启动 DSH，刷新页面

脚本会先确认 DSH 已退出、备份 profile 配置，再执行安装并逐项校验：依赖是否
登记、包能否解析、是否声明了 `dsh.bundle`、双半边文件是否齐全。任一步失败都会
停下并打印回滚命令。

安装完成后，Host 日志里会出现：

```
[yoimiya-theme] Host 半边就绪（9/9 条路由）
```

## 卸载

**应用内**：设置 → 插件 → 找到 `dsh-yoimiya-theme` → 移除。

**命令行**：

```bash
dsh plugin --profile web remove dsh-yoimiya-theme
```

**Desktop 手动安装的**：

```powershell
& "$env:APPDATA\dsh-desktop\harness\.desktop-bin\pnpm.cmd" `
  --dir "$env:APPDATA\dsh-desktop\harness\profiles\web" `
  remove dsh-yoimiya-theme
```

卸载后配色与样式会一并撤销，不留残留；**曲库文件夹与里面的音乐不受影响。**

## 后续与贡献

这个主题还在继续打磨。下面几条是已知可以更好的方向，也欢迎你提别的：

- **性能**：粒子层现在是 Canvas 2D。**如果将来把密度做大**（几千个粒子），值得
  换成 WebGL——把物理放进顶点着色器（重力是线性的、阻力是指数衰减，都有闭式解），
  每帧 CPU 只剩一次 draw call。但**现在这个密度下不划算**：拖尾要改成 FBO 乒乓，
  还得永久保留一条 2D 回退路径，等于为纯装饰层维护两套渲染器
- **更多意象**：更多宵宫相关的配色档，或背景变体
- **播放器**：播放模式（单曲循环 / 随机）、歌词显示

**欢迎 PR。** 有几条约定能让改动好验收：

- **改 `bundle/host.js` 必须完全重启 DSH 才生效**；改 `bundle/client.js` 存盘后
  刷新页面即可。不知道这条会浪费很多时间在"改了没反应"上
- **改过 `assets/` 里的任何文件，要把 `bundle/client.js` 里的 `ASSET_V` 加一**，
  否则新图永远出不来（资源带 `max-age=3600`，靠查询串换 URL 穿透缓存）
- **明暗两档的标识几何必须逐字一致**，只允许换颜色，否则明暗切换时像换了个 logo
- 提交前跑一遍仓库自带的自检，它们会拦住绝大多数回归：

```bash
node tools/verify.mjs          # 设计契约自检：token、对比度、禁用项、发布清单、标识几何
node tools/live-check.mjs      # 确认运行中的 DSH 到底在发哪一版
node tools/test-cover-flow.mjs # 封面流程端到端回归（两条裁切路径）
node tools/test-list-songs.mjs # 曲库列举回归
```

设计推导、改配色与换图的具体步骤、以及开发时容易踩的坑，见
[`DESIGN.md`](./DESIGN.md)。
